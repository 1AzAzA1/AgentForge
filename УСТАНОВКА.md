## 1. Что понадобится

| Требование | Подробности |
|---|---|
| Операционная система | Windows 10/11, macOS 12+, Linux с графической оболочкой |
| Python | **3.11 или новее** (проверено на 3.12) |
| Свободное место | около 600 МБ (основную часть занимает PySide6) |
| Оперативная память | от 2 ГБ; при 10+ агентах лучше 4 ГБ |
| Интернет | нужен для установки и для облачных моделей. С Ollama приложение работает полностью офлайн |
| API-ключ | хотя бы один - свой. Приложение не содержит встроенных ключей и ничего не оплачивает за вас |

Отдельный графический сервер на Linux обязателен: это десктопное приложение,
на сервере без X11/Wayland оно не запустится.

## 2. Установка Python

Проверьте, установлен ли он уже. Откройте терминал (на Windows -
**командную строку** или **PowerShell**) и выполните:

```bash
python --version
```

Если команда не найдена, попробуйте `python3 --version`. Нужен ответ вида
`Python 3.11.x` или выше.

**Windows.** Скачайте установщик с [python.org](https://www.python.org/downloads/).
При установке **обязательно** отметьте галочку **«Add Python to PATH»** на
первом экране - без неё команда `python` не заработает.

**macOS.** Либо установщик с python.org, либо через Homebrew:

```bash
brew install python@3.12
```

**Linux (Ubuntu/Debian).** Понадобится сам Python, модуль venv и системные
библиотеки для Qt:

```bash
sudo apt update
sudo apt install python3 python3-venv python3-pip \
     libgl1 libegl1 libxkbcommon-x11-0 libdbus-1-3 \
     libxcb-cursor0 libxcb-icccm4 libxcb-keysyms1 \
     libxcb-randr0 libxcb-render-util0 libxcb-shape0 \
     fonts-dejavu
```

Последний пакет, `fonts-dejavu`, нужен для экспорта в PDF с кириллицей.
На Fedora: `sudo dnf install python3 python3-pip mesa-libGL dejavu-sans-fonts`.

## 3. Запуск в один шаг

Самый простой путь. Скрипт сам создаст виртуальное окружение, поставит
зависимости и запустит приложение.

**Windows** - дважды щёлкните по файлу `run.bat` в папке проекта.
Сообщения этого скрипта написаны латиницей намеренно: консоль Windows
использует устаревшую кодовую страницу и показала бы кириллицу
нечитаемой.

**Linux и macOS** - в терминале:

```bash
cd путь/к/AIOrchestrator
./run.sh
```

Первый запуск занимает 2-5 минут: скачивается PySide6, он довольно большой.
Последующие запуски - пара секунд.

Если у вас несколько версий Python, укажите нужную явно:

```bash
PYTHON=python3.12 ./run.sh
```

## 4. Запуск вручную

Если хотите контролировать процесс или скрипт не подошёл.

```bash
cd путь/к/AIOrchestrator

# 1. Создать виртуальное окружение
python -m venv .venv

# 2. Активировать его
#    Windows (командная строка):
.venv\Scripts\activate
#    Windows (PowerShell):
.venv\Scripts\Activate.ps1
#    Linux и macOS:
source .venv/bin/activate

# 3. Установить зависимости
pip install --upgrade pip
pip install -r requirements.txt

# 4. Запустить
python main.py
```

Виртуальное окружение нужно, чтобы зависимости приложения не конфликтовали
с другими вашими проектами. В следующий раз достаточно шагов 2 и 4.

Если PowerShell отказывается выполнять скрипт активации, разрешите это для
текущего пользователя:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```

### Минимальная установка

Если экспорт в DOCX и PDF не нужен, хватит четырёх пакетов:

```bash
pip install PySide6 qasync httpx cryptography
```

Приложение запустится, а недостающие форматы экспорта просто скажут, чего
им не хватает.

## 5. Первый вход: создание профиля

При первом запуске откроется окно входа с предложением создать профиль.

Придумайте имя профиля и пароль **не короче 8 символов**.

> **Важно.** Пароль профиля одновременно является мастер-ключом, которым
> шифруются ваши API-ключи. Восстановить его невозможно - механизма
> «забыли пароль» здесь нет и быть не может, иначе шифрование не имело бы
> смысла. Если пароль потерян, придётся создать новый профиль и добавить
> ключи заново.

На одном устройстве можно завести несколько профилей - например, рабочий и
личный. Данные профилей полностью изолированы друг от друга.

Галочка «Запомнить пароль в хранилище ОС» использует системное хранилище
секретов (Диспетчер учётных данных в Windows, Keychain в macOS, Secret
Service в Linux). Удобно, но на общем компьютере лучше её не включать.

## 6. Подключение API-ключей

Перейдите в раздел **«API-ключи»** и нажмите **«Добавить ключ»**.
Выберите провайдера - base URL подставится автоматически.

| Провайдер | Где взять ключ | Платно |
|---|---|---|
| OpenAI | platform.openai.com/api-keys | да |
| Anthropic (Claude) | console.anthropic.com/settings/keys | да |
| Google Gemini | aistudio.google.com/app/apikey | есть бесплатная квота |
| Groq | console.groq.com/keys | щедрый бесплатный лимит |
| OpenRouter | openrouter.ai/keys | часть моделей бесплатна (суффикс `:free`) |
| **Ollama** | ключ не нужен | бесплатно, работает офлайн |
| Hugging Face | huggingface.co/settings/tokens | ограниченная бесплатная квота |
| Свой endpoint | LM Studio, vLLM, llama.cpp, корпоративный шлюз | - |

После сохранения нажмите **«Проверить»**. Приложение запросит список моделей:
это подтверждает, что ключ рабочий, и заодно кэширует модели для выпадающего
списка при создании агентов. Наверху списка стоят рекомендованные модели,
проверенные с агентами и инструментами, ниже остальные модели провайдера.

Особенности провайдеров (сентябрь 2026):

* **Gemini.** Модели 2.5 доступны только тем, кто пользовался ими раньше, а
  2.0 отключены. С новым ключом выбирайте 3.x, например `gemini-3.8-flash`
  или более дешёвую `gemini-3.5-flash-lite`.
* **OpenAI.** Для агентов с инструментами подходят `gpt-5.4`, `gpt-5.4-mini`,
  `gpt-6-luna` и `gpt-6-sol`. Флагманы `gpt-6-astra` и `gpt-6.1-sol` вызывают
  инструменты только через Responses API: их можно взять через OpenRouter или
  дать агенту без инструментов.

Ключи хранятся зашифрованными (AES-256-GCM) в локальной базе. Они не
покидают ваше устройство, кроме запросов к самому провайдеру.

## 7. Бесплатный вариант без единой копейки

Если платить за токены не хочется, соберите систему на локальных моделях.

**Шаг 1.** Установите [Ollama](https://ollama.com/download) - он есть под
все три ОС.

**Шаг 2.** Скачайте модель. Хороший выбор для начала:

```bash
ollama pull qwen2.5:7b-instruct     # ~4.7 ГБ, работает на 8 ГБ ОЗУ
ollama pull qwen2.5:14b-instruct    # ~9 ГБ, заметно умнее, нужно 16 ГБ
```

**Шаг 3.** Убедитесь, что сервер запущен - обычно он стартует сам:

```bash
ollama list
```

**Шаг 4.** В приложении добавьте ключ с провайдером **Ollama (локально)**.
Поле ключа останется пустым, base URL подставится сам
(`http://localhost:11434/v1`). Нажмите «Проверить» - должен прийти список
скачанных моделей.

Дальше всё работает как обычно, но без интернета и без счетов. Качество
результата, конечно, будет скромнее, чем у крупных облачных моделей.

**Промежуточный вариант:** исполнителей оставить на облачной модели, а
супервайзера перевести на Ollama. Супервайзер читает каждый отчёт и на
реальных задачах съедает заметную долю бюджета, так что экономия выходит
ощутимая. Как это настроить - в разделе 10.

## 8. Создание агентов

Сначала создайте воркспейс в разделе **«Воркспейсы»** - это отдельный
проект со своими агентами, задачей и историей. Проектов может быть
сколько угодно, они не мешают друг другу.

Затем в разделе **«Агенты»** нажмите **«Создать агента»**:

1. **Шаблон роли** - аналитик, разработчик, тестировщик, критик,
   документатор, исследователь. Шаблон подставит системный промпт и
   разумный набор инструментов; всё это можно свободно править.
2. **Ключ и модель** - выберите подключённый ключ, затем модель.
   Кнопка «Загрузить список моделей» запросит актуальный перечень.
3. **Инструменты** - веб-поиск, чтение страниц, работа с файлами,
   исполнение кода в песочнице. Давайте только те, что нужны роли:
   аналитику ни к чему запускать код.
4. **Температура** - 0.2-0.4 для проверяющих и аналитических ролей,
   0.7-0.9 для генеративных.

Для разумного старта хватает трёх агентов: аналитик, исполнитель, критик.
Жёсткого ограничения нет - интерфейс рассчитан и на 15+.

**Агенты полностью изолированы друг от друга.** Они не видят промптов и
переписки коллег: история каждого хранится отдельно и выбирается только по
его идентификатору. Единственный канал обмена - анонимная сводка
супервайзера.

## 9. Первая задача от начала до конца

**Поставьте задачу.** Вкладка **«Задача»**: название, подробная
формулировка, при желании лимит токенов (пустое поле - без лимита) и
формат результата (оставьте «определить автоматически»).

**Разбейте на подзадачи.** Либо вручную кнопкой «Добавить подзадачу», либо
кнопкой **«Разбить автоматически (ИИ)»** - модель предложит 3-8 подзадач и
сама распределит их по ролям. Предложенное разбиение можно править:
переименовывать, менять порядок, переназначать исполнителей, удалять лишнее.

Если одна подзадача зависит от другой, зависимость задаётся в её карточке -
оркестратор запустит её только после завершения предшественницы.

**Запустите.** Раздел **«Выполнение»**, кнопка «Запустить агентов».
Слева пойдёт прогресс по подзадачам, справа - живая лента: какой агент
думает, какой инструмент вызвал, что ответил супервайзер.

Кнопки «Пауза» и «Остановить» работают в любой момент.

**Следите за расходом.** Вкладка **«Дашборд»**: счётчики, полоса прогресса
по статусам, графики расхода нарастающим итогом и в разрезе агентов.

**Отвечайте на вопросы.** Если включён human-in-the-loop (по умолчанию да),
в критических точках система остановится и спросит вас - карточка появится
прямо на экране «Выполнение». Варианты: принять, вернуть на доработку с
комментарием, пропустить подзадачу, остановить прогон.

**Заберите результат.** Вкладка **«Экспорт»**: формат подбирается
автоматически, причина выбора написана рядом. Отметьте, что включать
в документ, и нажмите «Экспортировать».

## 10. Настройка супервайзера

Вкладка **«Настройки»**, блок «Воркспейс».

**Режим «Свой API-ключ»** - супервайзером работает один из ваших агентов.
Выберите его в списке. Логично назначить сюда агента с самой сильной
моделью: он проверяет чужую работу.

**Режим «Локальная модель»** - проверки уходят на Ollama и становятся
бесплатными. Укажите модель (по умолчанию `qwen2.5:7b-instruct`) и base URL.

**Интервал сводок** - как часто супервайзер рассылает анонимную выжимку
всем агентам. Плюс отдельный переключатель «Сводка при завершении подзадачи».

> Сводки - главная статья расхода токенов у супервайзера. На тестовом
> прогоне из трёх подзадач он израсходовал около двух третей всех токенов
> проекта. Если счёт растёт быстрее ожидаемого, первым делом увеличьте
> интервал или выключите «Сводка при завершении подзадачи».

**Порог уверенности** - если исполнитель сам оценил свою уверенность ниже
этого значения, система остановится и спросит вас. Ноль отключает триггер.

**Пауза после каждого этапа** - спрашивать подтверждение перед запуском
следующей волны подзадач. По умолчанию выключено.

**Бюджеты** настраиваются на отдельном экране: лимиты по токенам и деньгам
для всего проекта, текущей задачи и каждого агента, плюс порог алерта.
Проверка идёт перед каждым вызовом модели, так что лимит реально
останавливает работу, а не сообщает о перерасходе постфактум.

## 11. Безопасность и песочница

**Исполнение кода.** Если у агента включён инструмент `code_exec`, он может
запускать код. Есть два режима, выбираются в настройках воркспейса:

*Docker* - настоящая изоляция: сеть отключена, файловая система
одноразовая, ограничены память, процессор и число процессов. Если Docker
установлен и запущен, режим «Авто» выберет его сам.

*Отдельный процесс* - работает везде без дополнительных установок:
одноразовый каталог, ограничения по процессору, памяти и размеру файлов,
вычищенное окружение без ваших ключей, сеть отрезана. **Но это не полная
изоляция:** процесс по-прежнему может читать файлы, доступные вашему
пользователю. Для чувствительных задач ставьте Docker.

**Доступ к файлам.** По умолчанию агенты работают только в каталоге своего
воркспейса. Дополнительные каталоги добавляются вручную в настройках.
Не добавляйте туда системные папки и каталоги с личными данными: агент
получит в них и чтение, и запись.

**Веб-поиск** работает через DuckDuckGo без ключа. При желании можно
переключиться на Tavily или Brave, если у вас есть их ключи.

## 12. Где лежат данные и как сделать резервную копию

| Система | Каталог |
|---|---|
| Windows | `%APPDATA%\agent-forge` |
| macOS | `~/Library/Application Support/agent-forge` |
| Linux | `~/.local/share/agent-forge` |

Внутри: `app.db` (база SQLite), `logs/` (журналы), `workspaces/` (рабочие
файлы агентов), `exports/` (выгрузки), `settings.json`.

Каталог можно перенести куда угодно через переменную окружения:

```bash
AIORC_HOME=/путь/к/данным ./run.sh
```

**Резервная копия** - просто скопируйте весь каталог. Зашифрованные ключи
останутся зашифрованными: без пароля профиля они бесполезны, так что копию
можно хранить относительно спокойно.

**Полный сброс** - удалите каталог целиком. Приложение создаст его заново
при следующем запуске.

## 13. Проверка работоспособности

В комплекте есть набор смоук-тестов. Он не ходит в интернет, не тратит
токены и проверяет логику ядра на подменных моделях:

```bash
# при активированном окружении
python tests/smoke.py
```

Ожидаемый результат - `ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ: 37 из 37`. Тесты работают во
временном каталоге и не трогают ваш профиль.

Интерфейс проверяется отдельным сценарием. Он проходит весь путь пользователя
от регистрации до экспорта и сохраняет скриншоты каждого экрана (путь
печатается в конце):

Для pytest нужны пакеты разработчика, приложению они не требуются:

```bash
pip install -r requirements-dev.txt
python tests/ui_tour.py shots      # скриншоты всех экранов в папку shots
python -m pytest                   # все тесты разом, включая интерфейс
```

Ожидаемый результат тура - `Сообщений QML с предупреждениями: 0` и все
подзадачи в статусе `done`. У pytest - все тесты зелёные.

Полезно прогнать их после изменений в коде или если поведение кажется
странным: они быстро покажут, сломано ядро или дело в настройках.

## 14. Если что-то не работает

**`python: команда не найдена`**
Python не установлен или не добавлен в PATH. На Windows переустановите с
галочкой «Add Python to PATH». На Linux и macOS попробуйте `python3`.

**`ModuleNotFoundError: No module named 'PySide6'`**
Зависимости не установлены или запуск идёт мимо виртуального окружения.
Активируйте окружение и выполните `pip install -r requirements.txt`.

**Linux: `qt.qpa.plugin: Could not load the Qt platform plugin "xcb"`**
Не хватает системных библиотек. Установите пакеты из раздела 2. Если не
помогло, посмотрите подробности:

```bash
QT_DEBUG_PLUGINS=1 python main.py
```

**Linux в WSL: окно не появляется**
Нужен WSLg (Windows 11) или внешний X-сервер. В WSL1 графика не работает.

**Окно открылось, но интерфейс выглядит гигантским или крошечным**
Проблема масштабирования на HiDPI. Попробуйте:

```bash
QT_SCALE_FACTOR=1 python main.py
```

**«Не удалось подключиться» при проверке ключа**
По очереди: ключ скопирован целиком, без пробелов; на счету есть средства
или квота; base URL соответствует провайдеру; корпоративный прокси не
блокирует запрос. Для Ollama - проверьте, что сервер запущен (`ollama list`).

**Ollama: `Connection refused`**
Сервер не запущен. Выполните `ollama serve` (на Windows и macOS он обычно
стартует сам вместе с приложением).

**Агенты не запускаются, кнопка «Запустить» неактивна**
Проверьте: задача сохранена, есть хотя бы одна подзадача, у подзадач
назначены исполнители, у агентов выбраны модель и ключ.

**Экспорт в PDF: «Не найден шрифт с поддержкой кириллицы»**
Встроенные шрифты PDF не знают кириллицу. Установите DejaVu
(`sudo apt install fonts-dejavu`) или выберите DOCX либо Markdown.

**Модель отвечает не в формате JSON при автоматическом разбиении**
Слабые модели иногда не держат формат. Попробуйте ещё раз, выберите модель
покрупнее или разбейте задачу вручную.

**Супервайзер съедает слишком много токенов**
Увеличьте интервал сводок, выключите «Сводка при завершении
подзадачи» или переведите супервайзера на локальную модель (раздел 10).

**Журнал ошибок**
Подробности всегда пишутся в файл:

```
<каталог данных>/logs/app.log
```

## 15. Сборка в исполняемый файл

Если хочется раздавать приложение без установки Python.

```bash
pip install pyinstaller

pyinstaller --name AgentForge --windowed --onedir main.py \
  --add-data "storage/schema.sql:storage" \
  --add-data "providers/pricing.json:providers" \
  --add-data "ui/qml:ui/qml" \
  --add-data "ui/assets:ui/assets"
```

Каталоги `ui/qml` и `ui/assets` обязательны: без них окно не откроется,
потому что интерфейс и шрифты читаются из файлов, а не из кода.

На Windows разделитель в `--add-data` - точка с запятой, а не двоеточие:
`--add-data "storage/schema.sql;storage"`.

Готовая сборка появится в `dist/AgentForge/`. Вариант `--onedir`
предпочтительнее `--onefile`: он запускается заметно быстрее.

Сборка получается только под ту систему, на которой выполняется: собрать
Windows-версию из Linux не выйдет.
